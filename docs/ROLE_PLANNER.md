# 导入角色设定并推演声线

首页「角色设定 → 声线推演」提供两步流程：先让本地语言模型根据人物设定提出声音设计，再将可编辑的声线提示词交给 VoiceDesign 生成音频。

## 使用方法

1. 导入 `.docx`、`.txt`、`.md` 或 `.json`，也可以直接粘贴设定。单个文件不超过 4 MB，提取后不超过 8000 字。
2. 检查左侧提取的文本，点击“根据设定推演声线”。建议包含人物年龄、性格、经历、说话习惯，以及你已经确定的声音特征。
3. 查看角色概括、声线建议、设定依据和待确认项。下方完整展示将要使用的声线提示词与角色试听台词，可以直接修改。
4. 点击“用这段提示词生成角色声音”。软件自动配置音频采样参数，并使用当前编辑后的提示词和台词生成试听。
5. 满意后点击音频下方的「保存这条声线到声线库」，填写角色名（描述选填）；保存时需确认已试听核对。也可以进入进阶设计页，刷新并加载对应会话，试听核对后保存。
6. 下次打开或刷新页面后，点击“刷新角色记录”，选择角色，再点击“恢复角色与试听”。记录按推演时间从新到旧排列，恢复原始设定、声线方案和最近一次成功生成时使用的提示词、台词与音频。

修改人物设定后需要重新推演，避免把旧角色的声音方案误用于新设定。修改声音提示词或试听台词则可以直接再次生成。
推演和生成期间暂时禁用相关输入，完成或报错后恢复操作。改动提示词或台词会清除当前试听，避免误以为旧声音对应新文字。

Word 仅提取 `.docx` 的正文及表格文字；不会识别图片、批注或扫描件。旧版 `.doc` 请用 Word 另存为 `.docx`。TXT 支持 UTF-8、带 BOM 的 UTF-16 和常见中文 GB18030 编码。JSON 会格式化显示，内容仍作为人物设定素材。

## 本地模型

语言模型使用官方 [Qwen3-1.7B](https://huggingface.co/Qwen/Qwen3-1.7B)，负责将角色设定转为结构化声线建议；音频仍使用已有 Qwen3-TTS VoiceDesign。模型会对缺少的信息提出创作建议，不能把性格与音色的对应关系当成确定事实，需要审阅和试听。

配置示例：

```toml
[planner]
python = "../external/qwen3-tts/.venv/Scripts/python.exe"
model = "../external/voice-planner/Qwen3-1.7B"
```

也可设置 `TIMBREFORGE_PLANNER_PYTHON` 和 `TIMBREFORGE_PLANNER_MODEL`。运行环境需要支持 Qwen3 的 Transformers、PyTorch 和 Accelerate；本机复用了已有 Qwen 隔离环境。固定模型版本见根目录 `planner-backend-lock.json`。

推演和语音生成均为独立本地进程，按同一串行队列执行：推演完成释放语言模型，然后加载语音模型。不会在推演时下载模型或将角色设定发往远端 API。CPU 会自动选择 FP32，可能较慢。

## 保存声线到声线库

试听满意后点击音频下方的「保存这条声线到声线库」，弹出保存面板：

1. **角色名（必填）**：默认填入推演得到的角色名，可以改。
2. **角色描述（选填）**。
3. **保存到**：选择「新建角色」，或选择已有角色来追加一条声线。**一个角色可以有多条声线**，用于对比不同提示词或不同种子得到的声音。
4. 需要勾选「我已试听，并确认这段音频与试听台词一致」。保存的是这条试听音频与它的台词，作为可复用参考声音；不是重新运行提示词，也不是训练模型。

右上方「声线库」按钮可查看已保存的角色与它们的全部声线，点选任一条目即可试听并查看当时使用的提示词。声线库只是一个索引文件（角色目录下的 `_voice-library.json`），音频与转录仍由角色卡保存；如果某张角色卡被删除或损坏，这条声线不会显示，也不会凭记录凭空出现。

保存后的声线可以直接在「角色复用」和「多角色项目」里作为参考声音使用。

## 生成记录与重新生成

- 音频下方是生成记录：**记录一 / 记录二 / 记录三**，最新的排在最前，点选即可切回之前生成的试听。
- 每条记录同时保存当时的提示词与台词。切回记录**只切换试听音频**，不会覆盖你输入框里正在编辑的文字，避免丢失未生成的改动。
- **最多保留 3 条**，再生成会删除最早的一条（只删除该角色目录下的 `generation-*.json`，不会碰角色存档和音频）。
- 「↻ 换个种子重新生成」会用当前输入框的提示词和台词再生成一条，每次使用新的随机种子，因此结果不同。它和「用这段提示词生成角色声音」是同一个动作，只是入口不同。

## 保存内容

设定原文、结构化方案、模型信息保存在配置输出目录的 `role-plans/<方案ID>/`。每次生成另存关联记录，包含编辑后的提示词、台词与音频会话 ID。生成音频仍在 `designs/` 中，可使用既有角色保存流程。

存档采用临时文件加原子替换，写入失败不会覆盖原记录。恢复时检查设定摘要、记录 ID、生成文字和音频校验值；音频丢失或不匹配会给出提示，并保留可重新生成的文字。损坏或结构不兼容的推演不会列入可恢复列表，原文件仍保留。只有推演成功及试听生成成功时自动存档；尚未生成的文字修改不会自动保存。

模型最多尝试两次输出结构化方案；格式持续不正确、缺文件或推演超时会显示错误并清空旧方案，避免旧内容冒充本次结果。

校验只对**会导致结果不可用或可能误导**的问题直接失败（缺字段、类型错误、超长、JSON 无效）。对风格偏差改为**可见提示**而不是让整次推演作废：特征条数不在 3–6、待确认项超过 4、试听台词过短，都会照常给出方案并在状态栏说明。依据未标注来源时不会凭空补上「设定：」，而是标为「未标注：」并提示自行判断——这一条来自本机实测：模型曾因输出「未说明口音，建议清晰普通话」而被旧的硬校验连续判失败两次，整次推演作废。
